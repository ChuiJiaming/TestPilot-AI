## Proposed first-phase engineering choices (not business-policy decisions)

- Keep PostgreSQL as the source of truth for authentication lifecycle, memberships, environment snapshots, and audit events.
- Resolve tenant ownership from database resources; never accept a client role or `org_id` as proof of authorization.
- Treat all migration files reconstructed from the Word document as candidates until tested on PostgreSQL 15+.
- Keep module API and database changes behind explicit contract tests; record any required endpoint additions before implementation.
- Password hashes use a versioned stdlib scrypt format in this candidate; confirm operational cost and rehash policy before production rollout.
- Registration for an existing email returns the same accepted response and does not change credentials; use the dedicated resend action for pending accounts. This is implemented to avoid account enumeration and credential replacement, but needs product review.
- M02 user-confirmed policy: project creator is `project_admin`; organization admins can manage and access all projects in that organization without a project-membership row. Project creation still requires organization membership.
